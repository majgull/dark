# Tasks: dark as an MCP server

This is the task list for the feature in `spec.md`, following `plan.md`. Tasks are the ordered checklist of steps that carry a plan out; do them in order, one commit each, and tick a box only when its acceptance command passes. An **acceptance command** is a command whose exit status says whether the step is done. `python3 -m unittest` is the test runner that ships with Python; `PATH` is the list of directories searched for a command, and the **fake dark** is the stand-in `dark` executable the tests put first on it, described in `plan.md`. Every commit also keeps `cd runner && bash verify.sh` green, which prints `verify OK`.

- [ ] 1. **The ledger-tail command.** Add the `ledger-tail` subparser (`--lines`, default 20; `--kind`) and `cmd_ledger_tail` to `runner/dark/__main__.py`, add `runner/tests/test_cli_ledger_tail.py` (last N rows, the kind filter, an empty ledger exits 0), and add the `dark ledger-tail` line under `## [Unreleased]` in `CHANGELOG.md`. Acceptance: `cd runner && python3 -m unittest tests.test_cli_ledger_tail -q`
- [ ] 2. **Framing.** Create `runner/dark/mcp.py` with the constants, `handle` and `serve`, answering `initialize`, ignoring `notifications/initialized`, and returning `-32601`, `-32700` and `-32600`; `TOOLS` is empty for now. Create `runner/tests/test_mcp.py` with the `Framing` group. Acceptance: `cd runner && python3 -m unittest tests.test_mcp.Framing -q`
- [ ] 3. **The subcommand.** Add the `mcp` subparser and `cmd_mcp` to `runner/dark/__main__.py`, add the `Pipes` group with a real `python3 -m dark mcp` subprocess that answers `initialize` and exits 0 when its standard input closes, and add the `dark mcp` line to `CHANGELOG.md`. Acceptance: `cd runner && python3 -m unittest tests.test_mcp.Pipes -q`
- [ ] 4. **The six tool definitions.** Fill `TOOLS` from the table in `spec.md`, answer `tools/list`, and add `validate` so a missing required argument, an unknown argument, a wrong type or an unknown tool returns `-32602`. Add the `ToolList` and `Validation` groups. Acceptance: `cd runner && python3 -m unittest tests.test_mcp.ToolList tests.test_mcp.Validation -q`
- [ ] 5. **The first call, and the fake dark.** Add `make_fake_dark`, `build_argv` and `tools/call`, and prove them on `dark_preflight`: the recorded argv, the returned text, an empty child standard input. Add the `ToolCalls` group. Acceptance: `cd runner && python3 -m unittest tests.test_mcp.ToolCalls -q`
- [ ] 6. **Run and ledger tail.** Cover `dark_run` (argv `shift --task-dir=... --tier=... --no-push`, with and without `think`) and `dark_ledger_tail` (`ledger-tail --lines=20` by default, `--kind=` when given) in `ToolCalls`. Acceptance: `cd runner && python3 -m unittest tests.test_mcp.ToolCalls -q`
- [ ] 7. **User, long and review.** Cover `dark_user`, `dark_long` and `dark_review` in `ToolCalls`, including `files` joined by commas and every optional argument. Acceptance: `cd runner && python3 -m unittest tests.test_mcp.ToolCalls -q`
- [ ] 8. **Failure paths.** Add the `Failures` group: exit code 3 gives `isError` true and a second item `exit code 3`, no `dark` on `PATH` gives `isError` true, and a value that starts with a dash reaches the fake as `--tier=-x`. Acceptance: `cd runner && python3 -m unittest tests.test_mcp.Failures -q`
- [ ] 9. **A whole session over pipes.** Extend `Pipes` to send `initialize`, `notifications/initialized`, `tools/list` and one `tools/call`, and assert that every line on standard output is JSON with the right id and that the process ends with exit code 0. Acceptance: `cd runner && python3 -m unittest tests.test_mcp.Pipes -q`
- [ ] 10. **The docs page.** Write `docs/mcp.md` as `plan.md` describes, add one line to the Documentation list in `README.md`, define "MCP server" once in `docs/concepts.md`, and extend the `CHANGELOG.md` entry to name `docs/mcp.md`. Acceptance: `grep -q 'docs/mcp.md' README.md && grep -q 'MCP server' docs/concepts.md && grep -q 'docs/mcp.md' CHANGELOG.md`
- [ ] 11. **The standard-library check.** Add an `Imports` test that parses `runner/dark/mcp.py` with `ast` and fails on any import outside `sys.stdlib_module_names` and the `dark` package, then run the whole gate. Acceptance: `cd runner && bash verify.sh`
