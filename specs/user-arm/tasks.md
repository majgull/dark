# Tasks: the user arm

This is the task list for the feature in `spec.md`, following `plan.md`. Tasks are the ordered checklist of steps that carry a plan out; do them in order, one commit each, and tick a box only when its acceptance command passes. An **acceptance command** is a command whose exit status says whether the step is done; run each from `runner/`. Every commit also keeps `cd runner && bash verify.sh` green, which prints `verify OK`. Items 1 to 6 were built before this spec was written and are recorded here so the list is whole; the rest are open.

- [x] 1. **Steps, verdicts and screenshots.** `run_steps` walks the steps, one screenshot and one `steps.jsonl` line per step, and the runner maps the tag to `pass` or `fail:capability`. Acceptance: `python3 -m unittest tests.test_user.Steps.test_three_steps_three_screenshots_in_order_and_three_verdicts tests.test_user.Driver -q`
- [x] 2. **A pass quotes the page.** A pass carries evidence found in the shown snapshot, or is refused and asked again. Acceptance: `python3 -m unittest tests.test_user.Steps.test_a_pass_whose_quote_is_not_on_the_page_is_refused_and_asked_again tests.test_user.Steps.test_a_pass_without_an_evidence_field_is_refused -q`
- [x] 3. **The third verdict and the trail.** `inconclusive` from the model, from calls exhausted and from the stuck rule; `steps/<NN>.trail.jsonl` and the `saw` note. Acceptance: `python3 -m unittest tests.test_user.Steps.test_a_model_inconclusive_verdict_is_recorded_and_never_fail tests.test_user.Trail -q`
- [x] 4. **Inconclusive is an outcome.** The runner keeps the `inconclusive` tag as the outcome `inconclusive`, outside `FAIL_OUTCOMES`, with the tally as its detail. Acceptance: `python3 -m unittest tests.test_run -q -k inconclusive`
- [x] 5. **A verdict is never stuck.** Only browser actions feed the stuck count; three identical refused passes end the step `evidence not found: ...`; a quote may span lines. Acceptance: `python3 -m unittest tests.test_user.Steps.test_a_refused_verdict_never_counts_as_stuck_and_names_the_quote tests.test_user.Steps.test_a_quote_spanning_two_snapshot_lines_matches -q`
- [x] 6. **Fragments, role prefixes and waits.** The quote is checked fragment by fragment against the snapshot without role prefixes, a refusal names the missing fragment, and a wait never counts toward stuck. Acceptance: `python3 -m unittest tests.test_user.Steps.test_a_quote_joining_two_elements_with_a_dash_is_accepted tests.test_user.Steps.test_a_quote_of_the_snapshot_format_with_role_prefixes_is_accepted tests.test_user.Steps.test_a_wait_never_counts_as_stuck_and_a_quote_still_passes -q`
- [ ] 7. **The words catch up with the third verdict.** Constitution rule 19 and the "step verdict" entry in `docs/concepts.md` still say a step is `pass` or `fail`, and the concepts entry says a failed step is the run's only other ending. Both name `inconclusive` and the `inconclusive` outcome, in the words of `spec.md`; rule 19 changes only with the owner's consent, because it is the constitution. Acceptance: `grep -q inconclusive ../docs/concepts.md && grep -n '^19\.' ../memory/constitution.md | grep -q inconclusive`
- [ ] 8. **A user task refuses `repos`.** `_load_user_task` refuses `repos` as it refuses `may_edit`, so a work-repo field is never silently dropped. Acceptance: a new test in `tests/test_tasks.py` passes and `bash verify.sh` prints `verify OK`.

Acceptance: `python3 -m unittest tests.test_user -q`

Acceptance: this item is ticked when every item it added is ticked.
